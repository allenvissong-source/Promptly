# Promptly・普罗

一个面向 AI 图片与视频创作的本地桌面工具，用来管理参考素材、编排结构化提示词，并把图片与文本快速复制到 ChatGPT 等生成式 AI 工具中。

Promptly 不直接调用模型 API。它负责把散落的图片、视频、音频和文字整理成可复用、可组合、可投喂的创作上下文，让“找素材 → 写提示词 → 组合分镜 → 复制投喂”的过程更稳定。

## 核心工作流

1. 创建项目，将图片、视频或音频导入项目素材库。
2. 把图片拖入生图区、模板区或分镜区，形成各自独立的素材集合。
3. 在编辑器中输入 `@`，插入图片引用；引用可显示为 `Image1` 等编号，也可显示为文件名。
4. 在模板区定义角色、场景或其他可复用提示词模块。
5. 在分镜区开启组合模式，引用模板并勾选需要的角色。
6. 单独复制某张卡片的图片或文字，或使用“复制全部”按顺序合并全部提示词。
7. 将剪贴板内容粘贴到 ChatGPT 或其他支持的生成工具中。

## 已实现功能

### 项目管理

- 创建、打开、重命名和删除项目。
- 项目数据、素材引用和编辑内容相互隔离。
- 首页展示项目列表，支持从顶栏快速切换项目。
- 删除项目时同步清理对应的本地素材目录。

### 素材库

- 管理图片、视频和音频，支持项目素材与全局公共素材。
- 通过文件选择器或拖入应用窗口导入素材。
- 支持多级文件夹、同级拖拽排序、素材移动与复制。
- 支持搜索，并按名称、时间或类型排序和筛选。
- 双击重命名；名称变化会同步到已经建立的素材引用。
- 通过内容哈希识别同一目标位置中的重复导入，并提示跳过。
- 导入时记录文件大小；安装 `ffprobe` 后可读取音视频时长。
- 图片缩略图预览、视频信息展示和音频播放/暂停。
- 右键可用系统默认程序打开文件、定位文件所在位置或复制文件。
- 删除素材时同时清理数据库记录、物理文件和相关引用，避免留下失效数据。

支持的常用格式：

- 图片：PNG、JPG/JPEG、GIF、WebP、BMP、SVG、AVIF
- 音频：MP3、WAV、OGG、FLAC、AAC、M4A
- 视频：MP4、MOV、MKV、AVI、WebM、FLV、M4V

### 生图区

- 以多个独立 cell 组织生图任务，可手动新建空白 cell。
- 将素材拖到空白区可创建新 cell，拖到已有 cell 可追加素材。
- 每个 cell 拥有独立的有序图片列表和提示词编辑器。
- 图片编号在每个 cell 内从 `Image1` 重新开始，并随排序实时更新。
- 支持单独复制本 cell 的图片和提示词。

### 模板区

- 创建和重命名多个可复用模板，适合描述角色、场景、服装、画风等内容。
- 每个模板拥有独立的素材列表和富文本提示词。
- 输入 `- 角色名：` 可生成稳定的角色实体，用于后续分镜组合。
- 可控制模板是否允许被分镜区引用。
- 可控制复制模板时是否带 `# 模板名` 标题。
- 支持项目图片与全局公共图片的 `@` 引用。

### 分镜区

- 创建多个有序分镜，每个分镜拥有自己的素材列表和提示词。
- 开启“组合模式”后，`@` 候选中会出现可引用模板。
- 模板引用会展示其中的角色，可按需勾选。
- 勾选角色时，可将该角色绑定的图片自动带入当前分镜。
- 复制时实时展开模板内容，只保留已勾选角色对应的行与普通文本。
- 模板改名、角色变化或删除后，引用会实时反映最新状态。

### 提示词引用与复制

- 基于 Tiptap 的结构化编辑器，图片引用、角色实体和模板引用均以不可拆分的 chip 保存。
- `@` 候选会在素材导入、移动、重命名或删除后即时刷新。
- 顶栏可在两种引用显示模式间切换：
  - 编号模式：`Image1`、`Image2`……
  - 文件名模式：显示去掉扩展名后的素材名称
- 显示模式保存在本地，下次启动仍会沿用。
- “复制全部”按生图区 → 模板区 → 分镜区的顺序合并非空内容，并解析所有引用。
- 单卡复制与全局复制均提供成功反馈。

### 保存与数据安全

- 使用顶栏保存按钮或 `Ctrl+S` 手动保存当前项目。
- 页面存在未保存修改时显示 dirty 状态。
- 关闭窗口、按 `Alt+F4` 或刷新前会提醒保存，避免误丢内容。
- 生图区、模板区和分镜区采用 SQLite 事务保存；任一步骤失败都会整体回滚。
- 数据完全保存在本机，不上传素材，也不依赖云端账号。

### 桌面体验

- 无原生标题栏的紧凑界面，将项目导航、保存、复制和窗口控制放在同一行。
- 支持拖动窗口、双击空白标题区最大化/还原，以及缩小、最大化和关闭。
- 三栏工作区与上下区域均可拖动调整尺寸。
- 深色界面，品牌名为 **Promptly・普罗**。

## 快速开始

### 环境要求

- Node.js 20.19+ 或 22.12+
- npm
- Rust stable（项目最低 Rust 版本为 1.77.2）
- Tauri 2 对应的系统编译依赖
- 可选：将 `ffprobe` 加入 `PATH`，用于读取音视频时长

> 当前主要在 Windows 上开发和验证。多文件原生剪贴板复制仅支持 Windows；macOS/Linux 可以编译其他能力，但该项会返回不支持提示。

### 安装与运行

```bash
npm install
npm run tauri:dev
```

只调试前端界面时：

```bash
npm run dev
```

浏览器模式不具备完整的本地文件、SQLite 和系统剪贴板能力，完整功能请使用 Tauri 桌面窗口。

### 构建桌面应用

```bash
npm run tauri:build
```

构建产物由 Tauri 写入 `src-tauri/target/release/bundle/` 下对应平台的目录。

## 技术栈

- 桌面框架：Tauri 2、Rust
- 前端：React 19、TypeScript、Vite 7
- UI：Tailwind CSS 3、shadcn/ui、Radix UI、Lucide
- 编辑器：Tiptap 3
- 本地数据：SQLite、`tauri-plugin-sql`
- 状态组织：React Context

## 本地数据说明

- SQLite 数据库使用 `sqlite:data.db`，由 Tauri SQL 插件保存在应用数据目录。
- 导入的文件会复制到应用数据目录下的 `uploads/common` 或 `uploads/<projectId>`。
- 素材库中的文件夹是数据库中的逻辑目录；物理文件按公共区或项目区保存。
- 提示词内容以 Tiptap JSON 保存，素材与模板引用保存稳定 ID，界面编号由当前顺序动态计算。
- 删除素材或项目属于破坏性操作，应用会先要求确认。

## 设计原则

- **本地优先**：素材、项目和提示词保存在本机。
- **引用而非粘贴**：编辑器保存素材 ID，名称与顺序变化可实时同步。
- **组合而非重复**：角色和场景沉淀为模板，分镜按需引用与展开。
- **显式保存**：避免后台自动保存产生异步写入竞态，保存行为由用户明确触发。
- **复制即交付**：保持与不同 AI 工具兼容，不把工作流绑定到某一家模型 API。

## 当前限制

- 多图片/多文件原生剪贴板复制目前仅在 Windows 上实现。
- 音视频时长依赖系统可执行的 `ffprobe`；缺失时显示 `00:00`，不影响导入。
- 应用目前不直接发起 AI 请求，也不管理模型密钥。
- 项目尚未配置自动化测试；每次发布前应至少通过 TypeScript、Vite 和 Rust 三项构建检查，并进行桌面端交互测试。

## 验证

```bash
npx tsc -b --force
npx vite build
cargo check --manifest-path src-tauri/Cargo.toml
```

以上检查通过后，仍建议在 `npm run tauri:dev` 中手动验证素材导入、拖拽、引用、复制、保存和窗口关闭保护。
